# E: narrow layouts, host theme and widget visibility

Issue #23, stacked on D PR #22 (`feat/21-refresh-backoff`). Design reviewed and amended per advisor; implementation pending. Three independently verified atomic commits: E1 layout, E2 theme, E3 showWidget. No SDK/package version change, new runtime dependency, extra settings framework, editor/footer takeover, automatic merge or release.

## E1: preserve fields before decoration

Keep widget and cache-backed details, active-model provider scope, account ordering/prioritization, stale/unknown/cached/error annotations, and D refresh policy. Shared small pure layout functions in `src/ui.ts` (or a small dedicated module if necessary) measure with Pi visibleWidth/sliceByColumn/truncateToWidth/wrapTextWithAnsi. No second renderer or arbitrary string-length column calculations.

Each quota's short window label and complete `left N%` are an indivisible semantic unit. Identity is expendable before that unit; shorten long identities first, then shorten/remove the bar, then split windows across rows. A normal wide card can still pack horizontally, with at most three columns. Multiline cards must remain grouped by account; do not interleave their rows with other accounts. Retain a distinct identity/header per account (not one indistinguishable shortened identity), and keep cached/stale/error warnings visible or explicitly omitted at the field level. A preserved number alone must not make cached data look current. Existing 8/6/4 bar-width packing may remain for already-fitting cards, but is not a guarantee at every width.

If even the no-bar quota unit cannot fit, show an explicit omission marker, never a partial number (e.g. `left 1` instead of `left 100%`). Do not split/abbreviate a duration to imply another window. Unknown remains unknown and zero remains zero; reset metadata cannot replenish quota. Render complete reset metadata separately if it does not fit beside the quota.

Balance amounts/signs and their required currency identifier are also atomic: split multiple currencies across lines rather than cutting an amount or sign. Currency symbols remain compatible with existing normal output; ambiguous identical symbols for different currencies must gain explicit codes. A truly over-wide single amount is omitted, not shown as a numeric prefix.

Details determine framing and inner width before laying out quota/balance rows. Labels, errors and other prose can wrap/truncate safely with explicit ellipses; their ANSI/control handling uses the existing sanitized snapshot boundary. Status/errors remain pinned; scroll body contains accounts and schedule metadata. Existing bounded height/close-key behavior remains. On extreme widths/heights only bounded markers/state/exit affordances may be representable; do not claim that all information fits every terminal.

Deterministic fixtures cover 30/40/80/120 columns, widths smaller than a full field, Chinese/wide/combining/emoji identities, long email and ANSI theme wrappers, multiple windows, 0/100 remaining, zero/negative/multiple-currency balances and cached failures. Assert full fields and no numeric prefixes, not width alone. Save sanitized synthetic text snapshots with reproducible tests; no screenshots/image generation or real accounts are needed.

## E2: semantic theme, fresh paint

Remove CLAUDE_ORANGE/fixed ANSI brand color. Providers use the same host semantic token (text or accent as appropriate to widget/details); normal bars/remaining numbers keep success/warning/error (<30%, <10%), with other freshness/error facts expressed separately. No custom palette, brightness detection or color math.

Use callback theme helpers during every render, never cache themed strings. Public Pi TUI/theme docs for the installed host and locked SDK have been read; invalidate clears caches and stateless rendering needs no rebuilt string store. Locked SDK's stable theme proxy was inspected only to understand the public callback behavior, not imported/accessed by implementation. Tests switch a proxy/closure's active light/dark palette and invalidate/re-render the same widget/details instance, proving no old ANSI survives. Where feasible replay a public host theme change in the disposable terminal fixture.

## E3: showWidget is presentation-only

Add required Settings.showWidget boolean with default true; missing legacy field normalizes true, only literal boolean values are accepted, invalid types warn and fall back to true. Use existing serialization, unknown-field/provider-key preservation, legacy migration, atomic writes and 0600 permissions. Add one independent SettingsList entry (enabled/disabled), restore it after save failure, and report visibility in status. Do not conflate provider toggles with display visibility.

Controller.renderCurrentModel clears widget and widget expiry timer immediately when hidden, while keeping provider state, source/provider cooldowns, refresh queue/operation ownership and details intact. Do not clear refresh status for in-flight work merely to hide the widget. Hidden details retain their existing local redraw and current snapshots; r still goes through D.

Handle showWidget before applySettings' ordinary scheduleRefresh branch. For a pure visibility change, adopt display settings and publish but do not restart/create periodic timers, change nextAutomaticCheckAt, cancel work, increment generation, request HTTP, reset source facts or close details. If callers also supply real source/provider changes, preserve existing invalidation rules; visibility must not disguise configuration boundaries. A minimal display revision marker protects the newest visibility choice against refreshes/config reads already in flight and old queued loaded settings, without changing lifecycle generation or cancelling HTTP. Queue merges must keep a loaded snapshot paired with its owning display revision. A normal later configuration read can still adopt an external visibility change. Test paused reads, fast toggles and old pending settings. No generic scheduler refactor is needed. External config loading/sync respects the boolean too; hiding must clear any already-scheduled widget expiry. Re-enable paints the latest cache immediately and schedules only the appropriate repaint boundary, not a provider query.

Tests use temporary settings, mocked fetch and fake Date/timers: toggle during live reads, after cooldown and with open details; same next tick before/after; periodic reads continue while hidden; no invisible widget expiry callbacks; details/r remain available and honor server wait; cache/last-valid/retry facts survive toggles. Settings UI tests drive the real component keyboard path and actual temp-file save success/failure (rather than replacing it with a synthetic controller stub). Verify unknown settings, strict normalization, default/migration behavior, atomic write cleanup and permissions.
